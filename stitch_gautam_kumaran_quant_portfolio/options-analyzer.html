In plain terms

What this project is actually doing

I built this to learn options trading by working with real data instead of only reading the theory.

The tool takes raw NSE options data, checks whether volatility is relatively high or low, looks at price trend and open interest, and then suggests a strategy that fits those conditions.

It also works out the strikes, breakeven points, maximum profit and loss, and then tests the same rules on previous monthly expiry cycles.

Overview

Turning raw options data into a repeatable decision process

The project is a learning tool, not a finished trading system. Its purpose is to make the logic behind strategy selection explicit and testable.

The problem

Options strategies are often described in broad terms, but choosing one requires a view on volatility, trend, support, resistance, and risk.

What was built

A set of Python modules for data collection, market analysis, strategy selection, trade construction, and backtesting.

Data

NSE F&O bhavcopy data for options contracts, together with historical spot-price data from Yahoo Finance.

Method

How the tool works

The pipeline is split into separate modules so the same analysis and strategy logic can be reused by the backtester.

01

Data collection

The data puller downloads NSE F&O bhavcopy files and historical spot prices, then cleans holidays, missing dates, and inconsistent formats.

02

Implied volatility and market conditions

Because NSE provides traded option prices rather than implied volatility, the tool solves for IV using the Black-Scholes model and Brent's numerical method. It also calculates IV Rank, SMA crossovers, ADX, open interest levels, and the put-call ratio.

03

Strategy selection

The indicators are combined into a market view: bullish, bearish, or range-bound, with volatility classified as relatively high or low. A rule-based matrix then ranks strategies and chooses strikes.

Rule-based, not machine learning
04

Trade details and backtesting

The strategy scorer calculates premiums, breakeven points, maximum profit, maximum loss, and probability of profit. The backtester then applies the same shared logic across historical monthly expiries and includes brokerage and slippage.

Current status

The pipeline works, but the strategy needs more testing

The project is still being improved and is not ready to be used for live trading.

What is working

The tool can collect and clean the data, calculate implied volatility, analyse market conditions, suggest strategies, construct the option legs, and run historical tests using the same shared functions.

What still needs work

Backtest performance is not consistently strong. The main areas being improved are strike selection, expiry handling, transaction-cost assumptions, and the overall strategy rules.

What I learned from it

The project gave me practical experience with raw exchange data, numerical IV calculation, option payoffs, and the difference between a strategy that sounds reasonable in theory and one that survives historical testing.
